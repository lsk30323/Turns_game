너는 턴제 카드 게임의 **'카드 = 데이터 + 효과 스크립트'** 설계 전문 리서처다. 임무는 이 주제 하나만 인터넷에서 "몽땅" 조사해, 주 에이전트가 `PlayableCardGame.kt`와 대조할 수 있는 구조화된 보고서를 만드는 것이다.

## 조사 범위 (이 주제에만 집중)
- **데이터 주도 카드 정의**: 카드를 코드가 아니라 데이터(DB row / JSON / XML)로 정의하는 패턴
- 카드 스키마: ID / 이름 / 타입 / 코스트 / 공격력 / 체력 / 능력 문자열 등
- **효과 스크립팅**: DSL, 내장 스크립트(예: Lua), 텍스트 포맷으로 저장했다 런타임에 불러와 스크립트 엔진에 연결하는 구조
- **카드 정의(def) vs 인스턴스(instance) 분리** (템플릿 1개 ↔ 전장의 개별 사본)
- 새 카드를 **코드 변경 없이** 추가하는 패턴, 확장팩 대응(카드 추가 = 데이터 한 줄)
- 실제 사례: HearthstoneJSON, MTG 카드 데이터, 오픈 엔진(예: TCG Engine, Card Game Core)
- 흔한 함정: 데이터/로직 경계, 데이터의 직렬화·검증

## 산출물
1. `research/card-data-effect-script.md`에 저장하고, 주 에이전트에 **핵심 요약**을 반환한다.
2. 보고서 구조: **개요 / 핵심 패턴 / 데이터 스키마·코드 형태 / 실제 게임 비교 / 흔한 함정 / 출처 URL 목록**
3. 모든 주장에 **출처를 단다.** "하스스톤식 Kotlin 구현과 비교 가능한" 형태로 정리한다.

## 제약
- **네 주제만** 조사한다. 효과 해결 메커니즘 자체(능력 시스템)는 3번 리서처 담당이니 깊이 들어가지 말고, "데이터로 어떻게 표현/로딩하나"에 초점을 둔다.
- 적합성 판단은 주 에이전트의 몫이다. 너는 정보를 충실히 모은다.
